# Site box kit: pravara edge node

The site box runs `apps/machine-adapter` as the **Sparkplug B Edge Node** of one
site. The site's printers are its **devices**. pravara's telemetry worker is
the **primary host application**. The box reaches the MQTT broker through
**Cloudflare Access (`cloudflared access tcp`)**. MQTT itself stays TLS end to
end, and the node signs in with its own MQTT credential.

> Boundary: this kit runs on the site box, outside the cluster. Broker
> listeners, Access applications, service tokens and node credentials are
> created on the platform side. Those steps go through Enclii, not this kit.

## What the box publishes and accepts

| Direction | Topic | Content |
|---|---|---|
| publish | `spBv1.0/{tenant}/NBIRTH/{edge}` | birth: `bdSeq`, `Node Control/Rebirth` |
| will / publish | `spBv1.0/{tenant}/NDEATH/{edge}` | death with the same `bdSeq` (MQTT will, QoS 1) |
| publish | `spBv1.0/{tenant}/DBIRTH/{edge}/{machine}` | every device metric: properties, capabilities, material slots, state, temperatures, job, command |
| publish | `spBv1.0/{tenant}/DDATA/{edge}/{machine}` | changed metrics only, by alias |
| publish | `spBv1.0/{tenant}/DDEATH/{edge}/{machine}` | printer unreachable |
| subscribe | `spBv1.0/{tenant}/NCMD/{edge}` | rebirth requests |
| subscribe | `spBv1.0/{tenant}/DCMD/{edge}/+` | `start_job`, `pause`, `resume`, `cancel` |
| subscribe | `spBv1.0/STATE/pravara-mes` | primary host online/offline. Births wait for `online` |

`{tenant}` is the pravara tenant slug. `{edge}` is `site-<slug>`. `{machine}` is
the machine **code** registered in pravara.

The full metric list is in `packages/sparkplug/README.md`. The per-node ACL is
generated by `sparkplug.EdgeNodeACL`.

`start_job` downloads the artifact over HTTPS and checks it against the
commanded SHA-256. Only a verified file is uploaded to the printer and started.
On a digest mismatch the printer is never contacted.

## Prerequisites

1. **Printers**
   - **Klipper/Moonraker** (e.g. Voron 2.4): Moonraker reachable on the LAN.
     Configure an API key if Moonraker's authorization requires one. Loaded
     filament is read from Moonraker's Spoolman component if one is
     configured. Otherwise it comes from the current file's `filament_type`.
   - **Bambu Lab** (e.g. A1): set **LAN Only** mode and enable **Developer
     Mode** on the printer. Note the serial number and the LAN access code.
     The printer's MQTT (8883) and FTPS (990) ports must be reachable from the
     box. Optionally, pin the printer certificate with `tls_pin_sha256`.
2. **pravara**
   - Every printer is pre-registered as a machine. Its machine code is the
     `device_id`. Attach it to this box with
     `PUT /v1/machines/{id}/sparkplug {"edge_node_id": "site-<slug>"}`.
   - The host quarantines a DBIRTH from a device that is not registered under
     this edge node (`discovered_machines`). It never trusts such a device
     automatically.
   - A tenant admin approves the box's enrollment (next section).
3. **Platform**
   - The broker hostname is protected by a Cloudflare Access application.
   - The box has an Access **service token**. Issuing one per box is a
     platform step (Enclii); this kit only reads it from
     `/etc/pravara-edge/cloudflared.env`.
   - You also need the broker's CA certificate.

## Enroll the box (no person handles the MQTT credential)

The box creates its own MQTT credential. pravara stores only a bcrypt hash of
it, and a person approves the box by a short, non-secret code.

1. In `config.yaml`, set `edge.enrollment_url` to the pravara API base URL
   (https) and keep `password_file` inside `state_dir`
   (`/var/lib/pravara-edge/mqtt_password`). Leave `username` empty: it
   defaults to `edge:<group_id>:<edge_node_id>`, the name pravara assigns.
2. Run the enrollment once:

   ```bash
   # container
   docker compose -f deploy/edge/compose.yaml run --rm edge -config /etc/pravara-edge/config.yaml -enroll
   # systemd install
   sudo -u pravara-edge /usr/local/bin/pravara-edge -config /etc/pravara-edge/config.yaml -enroll
   ```

   The box writes 32 random bytes to `password_file` (mode 0600), registers
   them with pravara and prints a user code such as `BCDF-GHJK`. The
   credential is never printed.
3. A tenant admin, signed in to pravara, approves the code for this edge node:
   `POST /v1/edge/enrollments/approve {"user_code": "BCDF-GHJK", "edge_node_id": "site-<slug>"}`.
   Machine credentials (API keys, service tokens) cannot approve. The code
   expires after 15 minutes; run step 2 again if it does.
4. The command exits once approved. Start the edge node as below.

Rotate the credential with `-enroll -rotate-credential`: the new credential
replaces the current one only after its approval. Revoke a box with
`POST /v1/edge/nodes/{id}/disable` (people only); the broker then refuses it.

## Install (container)

1. Lay out `/etc/pravara-edge/`. Secrets must be readable only by root and the
   container user:

   ```text
   /etc/pravara-edge/config.yaml          # from config.example.yaml
   /etc/pravara-edge/broker-ca.pem        # broker CA certificate
   /etc/pravara-edge/cloudflared.env      # TUNNEL_SERVICE_TOKEN_ID=..., TUNNEL_SERVICE_TOKEN_SECRET=...
   /etc/pravara-edge/secrets/<device>.moonraker_key | <device>.access_code
   ```

2. Copy `.env.example` to `deploy/edge/.env`.
   - Set `BROKER_HOSTNAME`.
   - Pin `CLOUDFLARED_IMAGE` to a released tag or digest.
3. In `config.yaml`, set `broker_url: ssl://cloudflared:8883` and
   `tls_server_name` to the broker's certificate name.
4. Build, enroll (previous section), then start it:
   `docker compose -f deploy/edge/compose.yaml up -d --build`. The MQTT
   credential lives in the `edge-state` volume.

## Install (systemd, no containers)

1. Build the binary on any machine:

   ```bash
   cd apps/machine-adapter
   GOWORK=off GOOS=linux GOARCH=arm64 go build -o pravara-edge ./cmd/adapter
   ```

2. Install it as `/usr/local/bin/pravara-edge`. Also install `cloudflared`.
3. Create a system user: `useradd --system pravara-edge`.
4. Copy the units from `systemd/` and enable them:
   - `pravara-edge-cloudflared.service` reads `BROKER_HOSTNAME` and the
     service token from `/etc/pravara-edge/cloudflared.env`.
   - `pravara-edge.service`.
5. In `config.yaml`, set `broker_url: ssl://127.0.0.1:8883` and
   `server.host: 127.0.0.1`.

## Dry run with simulators

Set `edge.simulate: true`. Every configured printer is then replaced by a local
protocol simulator: Moonraker HTTP, or Bambu MQTT-TLS plus FTPS. The node
connects to the broker and publishes births and data. It accepts commands
against the simulators. No printer on the network is contacted.

Use simulate mode to validate the credential, the Access path and the host
side before you connect printers.

## Check

- `curl -s http://127.0.0.1:4503/health` returns `status` and `edge.born`.
  It reports `degraded` until the node has published its birth.
- `curl -s http://127.0.0.1:4503/api/v1/devices` lists each printer with
  online/state/job.

The HTTP surface is read-only and local. Machines are declared in the config
file. Commands arrive only as Sparkplug DCMD over the authenticated broker
session.

## Troubleshooting

| Symptom | Check |
|---|---|
| `degraded`, never born | The primary host has not published `online` on `spBv1.0/STATE/pravara-mes`. Or the credential or ACL is rejected (see the broker logs): enrollment not approved yet, or the node was disabled. Or the Access token is wrong (see the `cloudflared` logs). |
| `-enroll` fails with `unknown_group` | `group_id` is not the pravara tenant slug. |
| `-enroll` ends with status `expired` | Nobody approved the code in time. Run it again; a new code is issued. |
| A printer never appears | The printer is unreachable from the box. Or the API key/access code is wrong. Or the `definition` id is wrong. |
| `DDEATH` repeatedly | The network to the printer is unstable. Raise `offline_after`. |
| `start_job` fails with `artifact digest mismatch` | The artifact URL served different bytes than commanded. Nothing was sent to the printer. |
| Bambu `start_job` fails after upload | Check that LAN Only + Developer Mode are on. Check the FTPS port (990). |
